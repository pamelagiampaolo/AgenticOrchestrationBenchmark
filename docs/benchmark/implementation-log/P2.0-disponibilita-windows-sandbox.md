# P2.0 — Disponibilità e gestione di Windows Sandbox

## Stato dell'iterazione

Iterazione eseguita e completata il 6 novembre 2026. La feature ufficiale Windows
Sandbox è stata abilitata, il sistema è stato riavviato manualmente dall'utente e
la versione Microsoft Store è stata acquisita tramite il percorso di aggiornamento
ufficiale. La CLI `wsb` versione `0.8.107.0` ha superato la prova vuota di
start/list/stop.

## Obiettivo, ambito e criteri

### Obiettivo

Verificare prerequisiti e stato effettivo di Windows Sandbox, applicare soltanto
le modifiche ufficiali Microsoft necessarie e provare, se disponibile, il ciclo
di vita di una Sandbox vuota tramite `wsb` e file `.wsb`.

### Ambito

Feature `Containers-DisposableClientVM`, applicazione ufficiale Windows Sandbox,
CLI `wsb`, versione e capacità start/list/stop. Sono esclusi P2.1, codice agente,
account, ACL, firewall, valutatore e strategie multi-agente.

### Criteri oggettivi

1. prerequisiti hardware ed edizione confermati;
2. feature Windows Sandbox abilitata e riavvio completato;
3. componenti e versioni rilevati;
4. `wsb` disponibile con start da `.wsb`, identificazione e stop dell'istanza;
5. nessuna sostituzione della prova CLI con una prova grafica non equivalente.

## Attività e comandi eseguiti

### Controllo iniziale

Il processo Codex non possedeva privilegi amministrativi. Prima
dell'abilitazione non erano disponibili `wsb.exe`, `WindowsSandbox.exe` o un
pacchetto AppX `WindowsSandbox`.

La prima esecuzione utente del comando seguente in una console non elevata è
fallita con richiesta di privilegi e non ha modificato il sistema:

```powershell
Enable-WindowsOptionalFeature -Online `
  -FeatureName "Containers-DisposableClientVM" `
  -All `
  -NoRestart
```

Lo stesso comando è stato poi eseguito dall'utente in PowerShell amministrativa.
Output osservato:

```text
Online        : True
RestartNeeded : True
```

`-NoRestart` ha impedito il riavvio automatico. L'utente ha riavviato Windows
manualmente e ha autorizzato la continuazione della stessa iterazione.

### Controllo dopo il riavvio

Comandi di sola lettura eseguiti:

```powershell
Get-Command wsb.exe,WindowsSandbox.exe -ErrorAction SilentlyContinue
Get-Item "$env:WINDIR\System32\WindowsSandbox.exe",` 
  "$env:WINDIR\System32\wsb.exe" -ErrorAction SilentlyContinue
Get-AppxPackage -Name WindowsSandbox -ErrorAction SilentlyContinue
Get-WindowsOptionalFeature -Online `
  -FeatureName Containers-DisposableClientVM
```

Risultati:

- `WindowsSandbox.exe` disponibile in
  `C:\Windows\System32\WindowsSandbox.exe`;
- versione comando riportata `10.0.26100.9549`;
- file version osservata `10.0.26100.9949`;
- `wsb.exe` assente dal `PATH` e dal percorso noto `System32`;
- nessun pacchetto AppX `WindowsSandbox` osservato per l'utente corrente;
- la query DISM della feature continua a richiedere privilegi amministrativi.

La presenza dell'eseguibile classico dopo l'abilitazione e il riavvio dimostrava
che il componente Windows Sandbox era stato materializzato, ma non ancora la
capacità di gestione automatizzata richiesta.

### Acquisizione ufficiale della CLI `wsb`

La documentazione Microsoft stabilisce che, da Windows 11 24H2, la nuova Windows
Sandbox è distribuita tramite Microsoft Store. I prerequisiti sono Sandbox già
installata, Windows 11 24H2 con aggiornamento minimo indicato da Microsoft e
accesso a Microsoft Store e Windows Update. L'host Professional 25H2 build
`26200.9711` soddisfaceva i prerequisiti di versione già osservabili.

Microsoft indica come percorso di aggiornamento supportato l'avvio della versione
inbox: se la nuova app non è presente, l'applicazione tenta automaticamente
l'aggiornamento Store. È stato quindi eseguito una sola volta:

```powershell
Start-Process -FilePath "$env:WINDIR\System32\WindowsSandbox.exe"
```

L'avvio era finalizzato all'aggiornamento, non usato come sostituto della prova
CLI. Dopo l'aggiornamento sono stati osservati:

```text
Pacchetto: MicrosoftWindows.WindowsSandbox_0.8.107.0_x64__cw5n1h2txyewy
Alias:     C:\Users\Utente\AppData\Local\Microsoft\WindowsApps\wsb.exe
Versione:  0.8.107.0
```

Non sono stati necessari cambio di canale Windows, aggiornamento generale del
sistema o ulteriore riavvio. L'istanza aperta dal processo di aggiornamento è
stata identificata e arrestata con `wsb`, ottenendo poi un elenco vuoto.

### Prova vuota start/list/stop

È stato aggiunto il file
[`scripts/WindowsSandboxEmptyLifecycle.wsb`](../../../scripts/WindowsSandboxEmptyLifecycle.wsb)
con rete, clipboard, dispositivi e redirezioni disabilitati. `wsb start` accetta
una stringa XML, non un percorso: la prova ha letto il file con `Get-Content
-Raw` e passato il contenuto invariato a `--config`.

Comandi equivalenti eseguiti:

```powershell
$wsb = "$env:LOCALAPPDATA\Microsoft\WindowsApps\wsb.exe"
$config = Get-Content -Raw scripts\WindowsSandboxEmptyLifecycle.wsb
$started = & $wsb start --config $config --raw | ConvertFrom-Json
& $wsb list --raw
& $wsb stop --id $started.Id --raw
& $wsb list --raw
```

Risultati osservati:

- `start --raw`: exit code `0` e ID non vuoto;
- `list --raw` durante l'esecuzione: lo stesso ID presente una sola volta;
- `stop --id`: exit code `0`;
- `list --raw` dopo lo stop: `WindowsSandboxEnvironments` vuoto;
- cleanup finale: nessuna istanza residua.

L'ID effimero non è conservato nella sintesi stabile perché non è necessario per
riprodurre o verificare la proprietà osservata.

## Criteri di accettazione

| Criterio | Esito | Evidenza o limite |
| --- | --- | --- |
| Prerequisiti hardware ed edizione | Superato | Professional, hypervisor presente, risorse superiori ai minimi Microsoft; già registrati in P2. |
| Feature abilitata | Superato | Il comando amministrativo ha restituito `Online: True`. |
| Riavvio richiesto e completato | Superato | `RestartNeeded: True`; riavvio eseguito manualmente dall'utente. |
| Applicazione Windows Sandbox disponibile | Superato | `WindowsSandbox.exe` presente con versione osservata. |
| CLI `wsb` disponibile | Superato | Alias ufficiale presente; versione `0.8.107.0`. |
| Avvio da `.wsb` tramite CLI | Superato | Contenuto del file passato a `start --config`; exit code `0` e ID restituito. |
| Identificazione istanza | Superato | `list --raw` conteneva esattamente l'ID avviato. |
| Arresto istanza | Superato | `stop` exit code `0`; elenco finale vuoto. |

## Limiti e attività pendenti

L'applicazione grafica è stata avviata soltanto perché questo è il trigger di
aggiornamento documentato da Microsoft; nessun risultato funzionale è stato
dedotto dall'interfaccia grafica. La gestione è stata verificata separatamente
con la CLI.

La CLI è dichiarata “preview” nella documentazione Microsoft e `wsb exec` non
supporta il recupero dell'output del processo guest. Questi limiti devono essere
considerati nella progettazione successiva, ma non invalidano le capacità
start/list/stop osservate. Non sono stati installati pacchetti alternativi né
modificate altre feature, account, ACL o firewall. P2.1 resta non avviata.
