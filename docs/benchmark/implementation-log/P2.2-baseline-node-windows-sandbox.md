# P2.2 — Baseline Node.js in Windows Sandbox

## Stato e perimetro

Iterazione eseguita il 6 novembre 2026. Verifica esclusivamente la baseline
pubblica Node.js di `BenchmarkTarget` dentro una Windows Sandbox nuova e offline.
Non coinvolge MCP, Claude, agenti, valutatore o materiali riservati.

## Obiettivo, ambito e comportamento atteso

L'obiettivo è verificare che una copia pubblica riconducibile a un commit, con
runtime e dipendenze già predisposti sul PC, possa eseguire build, typecheck e
suite pubblica comune nel confine provato in P2.1.

La copia temporanea deve escludere `.git`, configurazioni e credenziali utente e
test riservati. Nel guest l'input è read-only, viene copiato sul disco effimero e
soltanto l'output dedicato è mappato in scrittura. Build, typecheck e 27 test
devono riuscire senza rete; l'input host deve rimanere integro e l'istanza deve
essere arrestata.

## Commit sorgente e limite di designazione

All'inizio della prova il repository era pulito; `HEAD`, `main` e `origin/main`
coincidevano con:

```text
b7a681ccad7c28a4fab7e5c01594a7073aef282c
```

Questo commit è il **commit sorgente operativo della prova**. Non viene qui
designato come baseline sperimentale definitiva: B1 dichiara ancora aperta tale
decisione. Il criterio relativo al commit è quindi superato per tracciabilità
della prova, con questo limite esplicito.

## Versioni e comandi ricavati dal benchmark

Da `package.json`, `package-lock.json` e dall'ambiente già installato:

- Node.js `v24.17.0`;
- npm `11.13.0`;
- TypeScript `7.0.2`;
- Vitest `5.1.0`;
- build: `npm run build`, che esegue `tsc`;
- typecheck: `npm run typecheck`, che esegue `tsc --noEmit`;
- suite comune: `npm test`, che usa `vitest.public.config.ts`.

Per ottenere un report strutturato senza cambiare la suite, il comando effettivo
è stato:

```text
npm test -- --reporter=json --outputFile=public-test-report.json
```

## Preparazione dei materiali

[`Invoke-NodeBaselineSandboxProbe.ps1`](../../../scripts/Invoke-NodeBaselineSandboxProbe.ps1)
crea una directory temporanea e usa `git archive` sul commit sorgente per
estrarre soltanto i file versionati di `BenchmarkTarget`. Aggiunge:

- l'albero `node_modules` già installato e coerente con il lock file;
- `node.exe`, `npm.cmd` e il modulo npm necessario;
- il wrapper guest
  [`Run-NodeBaselineGuest.ps1`](../../../experiments/legacy-isolation-probes/NodeBaselineSandboxProbe/Run-NodeBaselineGuest.ps1).

Prima dell'avvio rifiuta `.git`, `.gitconfig`, `.npmrc`, `.env` e
`tests/reserved`. Il pacchetto npm installato conteneva una `.npmrc` distributiva
vuota di 0 byte: la prima preparazione si è fermata correttamente prima di
avviare la Sandbox. Il file è stato escluso dalla sola copia temporanea e la
preparazione completa è stata ripetuta. Nessuna configurazione personale è stata
modificata o inclusa.

Il manifest host finale comprende 3.073 file e relativi hash SHA-256. Il digest
dell'intero manifest era identico prima e dopo:

```text
FB2049A90FCF0D6268627E47AF040C6FC92C6F2874DD640937E381669AA7866E
```

Il manifest dettagliato resta tra le evidenze temporanee host perché è grande e
contiene percorsi relativi di tutte le dipendenze; la sintesi priva di segreti è
versionata in
[`evidence/P2.2-node-baseline-sandbox-summary.json`](../evidence/P2.2-node-baseline-sandbox-summary.json).

## Configurazione Sandbox

La configurazione riusa P2.1: rete, vGPU, clipboard, stampanti, audio e video
disabilitati e `ProtectedClient` abilitato. I soli mapping sono:

1. input autorizzato in `C:\BaselineInput`, read-only;
2. output della prova in `C:\BaselineOutput`, scrivibile.

Il wrapper copia l'input in `C:\BaselineWork`, imposta npm in modalità offline e
avvia i tre comandi sulla copia locale. Nel guest non risultavano interfacce di
rete non-loopback attive.

## Risultati osservati

| Operazione | Exit code | Esito |
| --- | ---: | --- |
| `npm run build` | 0 | Superata |
| `npm run typecheck` | 0 | Superata |
| suite pubblica comune | 0 | 27 superati, 0 falliti, 0 pending |

Node e npm osservati nel guest coincidevano con le versioni host registrate.
`wsb exec` è terminato con exit code zero; lo stop è riuscito e `wsb list --raw`
ha riportato zero istanze attive.

I file `build/typecheck/test.stdout.txt`, i corrispondenti stderr e
`guest-result.json` erano nella directory `sandbox-output`. Manifest e report di
integrità erano in `host-evidence`, non mappata nel guest.

## Limiti

La prova riusa l'albero di dipendenze già installato: non esegue `npm ci` dentro
la Sandbox, perché la rete è disabilitata e non è stato preparato un cache npm
offline separato. L'integrità è attestata dal manifest della copia effettiva e
dalle versioni bloccate, ma questa iterazione non dimostra la ricostruzione delle
dipendenze partendo dal solo lock file.

Il risultato vale per le versioni e la build Windows osservate. Non certifica la
baseline sperimentale definitiva, i task individuali, MCP, Claude, il valutatore
o l'isolamento complessivo dell'esperimento.
