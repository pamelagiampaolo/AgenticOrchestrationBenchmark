# P2.1 — Prova di isolamento in Windows Sandbox

## Stato e perimetro

Iterazione eseguita il 6 novembre 2026. La prova riguarda esclusivamente build,
test e processi figli in Windows Sandbox. Usa soltanto sentinelle casuali
fittizie e un progetto C# minimo offline. MCP, Claude CLI, agenti, valutatore,
materiali riservati reali e strategie multi-agente non sono coinvolti.

## Obiettivo, ambito, comportamento atteso e accettazione

L'obiettivo è osservare se una Sandbox nuova, con rete e redirezioni disabilitate,
consente il lavoro interno autorizzato ma impedisce al processo principale e a un
figlio di raggiungere file, processi e rete del PC. L'ambito comprende un input
host fittizio mappato in sola lettura, un output non fidato distinto per fase,
evidenze host separate, arresto per timeout e verifica di non persistenza.

Il comportamento atteso è: build e test offline riusciti; lettura interna,
scratch e output riusciti; input read-only e risorse non mappate inaccessibili;
rete assente; arresto dell'intera istanza; nessun marker interno nella successiva
istanza. I dieci criteri oggettivi sono quelli definiti in
[P2](P2-isolamento-processi-codice-agente.md#criteri-oggettivi-di-accettazione-p21).

## Artefatti della prova

- `experiments/legacy-isolation-probes/P21IsolationProbe/MinimalCalculator.cs`: progetto minimo compilato offline;
- `experiments/legacy-isolation-probes/P21IsolationProbe/Run-P21GuestProbe.ps1`: wrapper guest fidato, build e test;
- `experiments/legacy-isolation-probes/P21IsolationProbe/Test-Isolation.ps1`: prove nel processo principale e figlio;
- `experiments/legacy-isolation-probes/P21IsolationProbe/Timeout-Probe.ps1`: marker e processo lungo per il timeout;
- `experiments/legacy-isolation-probes/P21IsolationProbe/Check-Persistence.ps1`: controllo nella nuova istanza;
- `scripts/legacy-isolation/Invoke-P21IsolationProbe.ps1`: harness host e configurazioni `.wsb`;
- `scripts/legacy-isolation/P21TcpSentinelServer.ps1`: endpoint TCP host con log delle connessioni;
- `evidence/P2.1-isolation-summary.json`: sintesi stabile priva di sentinelle.

L'harness crea ogni run sotto la directory temporanea dell'utente. Le directory
`sandbox-output-*` contengono esclusivamente report prodotti nel guest e sono gli
unici mapping scrivibili. `host-evidence` contiene manifest, log endpoint e
verifiche calcolate dal PC e non è mappata nella Sandbox. Configurazioni fidate,
risultati, output precedenti, credenziale simulata ed eseguibile host simulato
restano in directory temporanee non mappate.

## Configurazione osservata

La prova finale ha usato `wsb` `0.8.107.0` e Windows PowerShell
`5.1.26100.9711`. Ogni configurazione abilita `ProtectedClient`, disabilita rete,
vGPU, clipboard, stampanti, audio e video, e mappa soltanto:

1. input autorizzato come `C:\P21Input`, read-only;
2. output della singola fase come `C:\P21Output`, scrivibile.

Il wrapper guest copia l'input sul disco effimero e riduce l'ambiente, prima di
build, test e probe, a `ComSpec`, `PATH`, `PATHEXT`,
`PSExecutionPolicyPreference`, `PSModulePath`, `SystemRoot`, `TEMP`, `TMP` e
`windir`. La variabile `PSExecutionPolicyPreference` è aggiunta da PowerShell per
il flag `-ExecutionPolicy Bypass`; è tecnica e non contiene dati del PC.

## Comandi e verifiche eseguite

```powershell
# parsing di tutti gli script della prova
[System.Management.Automation.Language.Parser]::ParseFile(...)

# accettazione completa
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts\legacy-isolation\Invoke-P21IsolationProbe.ps1

# stato finale
wsb list --raw
```

L'harness ha inoltre eseguito e registrato:

- hash SHA-256 di input, harness, `powershell.exe`, `WindowsSandbox.exe` e delle
  tre configurazioni `.wsb` effettive;
- controllo positivo dell'endpoint dal PC prima delle prove guest;
- build tramite `Add-Type` e test per riflessione di `Add(2, 3) == 5`;
- gli stessi tentativi file, processo, ambiente e rete nel padre e nel figlio;
- hash delle sentinelle protette prima e dopo la Sandbox;
- stop dell'istanza con processo lungo e verifica dell'uscita di `wsb exec`;
- avvio di una nuova istanza e ricerca del marker interno precedente.

Una prima ripetizione irrobustita è terminata con exit code `1` perché PowerShell
aggiungeva `PSExecutionPolicyPreference` dopo la sanitizzazione. Questa era
l'unica verifica negativa. La variabile tecnica è stata aggiunta esplicitamente
all'allowlist e l'intera accettazione, non il solo controllo ambiente, è stata
ripetuta. La run finale è terminata con exit code `0`. Tutti gli script hanno
riportato zero errori di parsing e al termine `wsb list --raw` non elencava
istanze attive.

## Risultati osservati

- build e test offline: riusciti;
- lettura interna, ciclo scratch e scrittura output: riusciti nel padre e figlio;
- scrittura nell'input: negata nel padre e figlio;
- lettura/elenco delle cinque aree protette non mappate: negati;
- traversal, UNC e junction verso aree host: tentati e negati;
- lancio dell'eseguibile presente solo sul PC: negato e marker host assente;
- ambiente: corrispondenza esatta con l'allowlist nel padre e figlio;
- DNS pubblico, TCP pubblico, endpoint PC e indirizzo LAN: falliti nel padre e
  figlio; nessuna interfaccia non-loopback risultava attiva;
- endpoint: una connessione totale, coincidente con il controllo positivo dal
  PC; nessuna connessione aggiunta dalle Sandbox;
- sentinelle protette: hash invariati e valori assenti dagli output guest;
- timeout: intera istanza arrestata, processo `wsb exec` terminato;
- nuova istanza: marker interno precedente assente;
- stato finale: zero istanze Sandbox attive.

Nessun criterio è fallito nella run finale. Il criterio 10 rimane intenzionalmente
non dimostrato: P2.1 non introduce né simula le condizioni multi-agente.

## Limiti delle conclusioni

La prova supporta il confine candidato solo per versioni, configurazione e
vettori osservati. I percorsi assoluti host indicano nel guest uno spazio nomi
diverso; il risultato, insieme a mapping e sentinelle, dimostra l'assenza di
accesso per questi tentativi, non ogni possibile vulnerabilità del sistema.
L'allowlist è applicata dal wrapper fidato prima del codice sottoposto a prova,
non ai processi di bootstrap precedenti della Sandbox. Le prove di rete combinano
stato adattatori, più destinazioni e controllo positivo host, ma non enumerano
ogni API o protocollo Windows. Limiti di CPU, memoria, spazio e volume output non
sono provati in questa iterazione.

Questa prova non certifica MCP, Claude CLI, orchestratore, valutatore o isolamento
complessivo dell'esperimento. Il riepilogo stabile conserva solo versioni,
configurazione, conteggi ed esiti booleani; valori sentinella, ID delle istanze e
percorsi temporanei non sono versionati.
