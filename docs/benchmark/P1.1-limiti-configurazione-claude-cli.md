# P1.1 — Limiti residui della configurazione Claude CLI

## Iterazione

Iterazione eseguita il 5 novembre 2026 sulla Claude CLI `2.1.312`, limitata a
subagenti, plugin built-in, fonti di configurazione e hook del prototipo P1.

### Obiettivo

Determinare se agenti e plugin built-in possano attivarsi senza uno strumento di
delegazione esposto e stabilire quali configurazioni e hook possano ancora
raggiungere la sessione P1.

### Ambito

Documentazione ufficiale, help locale, configurazioni temporanee, hook-sentinella
fittizi e ripetizione completa dell'accettazione P1. Non sono state modificate
configurazioni personali e non sono stati introdotti codice agente, isolamento
OS, valutatore o strategie multi-agente.

### Criteri oggettivi

1. collegare la possibilità di delegare alla presenza effettiva del tool
   `Agent`;
2. osservare l'inventario dei tipi di subagente dopo la disabilitazione prevista
   per la modalità non interattiva;
3. osservare se i plugin built-in aggiungono tool, skill, agenti, slash command o
   MCP;
4. provare con controllo positivo che una configurazione hook fittizia valida si
   attivi quando abilitata e non si attivi nella configurazione P1;
5. distinguere fonti escluse, fonti ancora applicabili e fonti non osservabili;
6. ripetere tutti i controlli P1 dopo ogni modifica al launcher.

## Fonti ufficiali

- [Create custom subagents](https://code.claude.com/docs/en/sub-agents): senza
  `Agent` nell'elenco dei tool il thread principale non può generare subagenti;
  in modalità `-p`, `CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1` rimuove tutti i
  tipi built-in.
- [Environment variables](https://code.claude.com/docs/en/env-vars): conferma
  ambito e significato della variabile precedente.
- [Hooks reference](https://code.claude.com/docs/en/hooks): gli hook possono
  provenire da impostazioni user, project, local, managed e plugin;
  `disableAllHooks: true` fornito con `--settings` prevale su user/project/local,
  ma non può disabilitare hook imposti da managed settings.
- [Settings files and precedence](https://code.claude.com/docs/en/settings): le
  managed settings precedono `--settings`; variabili d'ambiente e configurazione
  globale seguono regole proprie.
- [Plugins overview](https://code.claude.com/docs/en/plugins): un plugin può
  contenere skill, agenti, hook, mod e server MCP; alcuni mod sono incorporati
  nella CLI.

L'help locale aggiunge che `--restricted` ignora impostazioni user, project e
local, ma applica managed settings e il file passato a `--settings`. Specifica
inoltre che `--tools ""` disabilita tutti i tool built-in e che `--safe-mode`
lascia funzionare normalmente tool e plugin incorporati.

## Modifica motivata al launcher

La configurazione fidata generata dal launcher ora contiene:

```json
{
  "disableAllHooks": true,
  "env": {
    "CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS": "1"
  }
}
```

Il launcher usa inoltre `--include-hook-events`. Nella prova aggiunge due hook
`SessionStart` fittizi: uno nella configurazione project, che `--restricted` deve
ignorare, e uno nel file `--settings`, che `disableAllHooks` deve neutralizzare.
Un'esecuzione di controllo separata usa un hook fidato equivalente con
`disableAllHooks: false`.

Comando finale:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Invoke-McpReadOnlyPrototype.ps1 -Mode All
```

### Risultati osservati

- il controllo positivo ha creato `hook-positive-control-fired.txt` con
  `HOOK_POSITIVE_CONTROL_EXECUTED`;
- il relativo stream ha registrato `hook_started` e `hook_response` per
  `SessionStart:startup`;
- la sessione P1 non ha creato le sentinelle project o trusted e non ha emesso
  eventi hook;
- `system/init.agents` è vuoto;
- `system/init.tools` contiene soltanto i due tool MCP P1;
- `skills` e `slash_commands` sono vuoti e l'unico MCP è `readonly`;
- i tre plugin `cc-plugin-agents-md`, `cc-plugin-telemetry` e
  `cc-plugin-plugin-authoring` restano dichiarati come `builtin`;
- nessun subagente è stato richiesto o creato;
- tutti i controlli originari P1 sono nuovamente `true`, inclusi lettura interna,
  tre rifiuti e mancata divulgazione della sentinella esterna;
- `claude doctor` continua a riportare policy organizzativa non applicabile
  all'account Pro/Max osservato.
- l'ambiente del launcher non conteneva nomi di variabili ereditate con prefisso
  `CLAUDE` o `ANTHROPIC`; i valori non sono stati stampati. Questo è un dato della
  singola esecuzione, non una garanzia per ambienti futuri.

## Conclusioni supportate

### Subagenti

Nella configurazione rafforzata i subagenti built-in non sono soltanto
inutilizzabili per assenza del tool `Agent`: non sono più presenti
nell'inventario iniziale. La documentazione ufficiale collega la generazione di
subagenti al tool `Agent`, assente da `system/init.tools`. Per la versione e la
modalità provate, non è disponibile una via di delegazione tramite il modello.

Questa conclusione riguarda la sessione `-p` avviata dal launcher. Non certifica
comandi esterni come `claude agents`, workflow o altre sessioni avviate fuori dal
launcher.

### Plugin built-in

I plugin built-in sono caricati o almeno dichiarati indipendentemente
dall'inventario dei tool e non possono essere descritti come assenti. Nella prova
non hanno aggiunto tool, skill, subagenti, slash command o MCP e i loro hook
ordinari sono soggetti a `disableAllHooks`. L'assenza di tali superfici è
osservata; non è dimostrata l'inattività di ogni comportamento interno, per
esempio telemetria o mod incorporati che la CLI non rappresenta come tool o hook.
`--safe-mode` non risolve questo limite perché, per documentazione e help locale,
lascia attivi i plugin incorporati e disabilita il server MCP richiesto da P1.

### Configurazioni e hook

| Fonte | Esito nella configurazione P1 |
| --- | --- |
| User, project e local settings | Ignorate da `--restricted`; la sentinella project lo conferma per il caso provato. |
| File esplicito `--settings` | Applicato; contiene i vincoli fidati. I suoi hook ordinari sono disabilitati da `disableAllHooks`. |
| MCP da altre configurazioni | Esclusi da `--strict-mcp-config`; un solo MCP connesso è osservato. |
| Plugin installati e relative personalizzazioni | Nessun plugin non built-in è apparso nella prova e le impostazioni user/project/local che possono abilitarli sono ignorate. Non è dimostrato in generale che `--restricted` escluda ogni plugin installato; i tre plugin built-in restano dichiarati. |
| Managed settings e hook managed | Possono ancora prevalere e non sono disabilitabili dal launcher. Il diagnostico corrente non ne rileva, ma il launcher deve ripetere questo controllo per ogni ambiente. |
| Variabili d'ambiente ereditate | Possono ancora influenzare chiavi specifiche secondo la documentazione; non sono state enumerate o sterilizzate integralmente. |
| Configurazione globale e autenticazione | L'autenticazione esistente è intenzionalmente conservata. `~/.claude.json` non è una fonte MCP grazie a `--strict-mcp-config`, ma non è stato dimostrato che nessun altro campo globale influenzi la sessione. |
| Hook di skill/agente | Nessuna skill o agente è presente nella sessione rafforzata. |

## Aspetti non dimostrati

- assenza di qualunque comportamento interno dei plugin built-in;
- esclusione generale di plugin installati che possano essere attivati da fonti
  diverse dalle impostazioni user/project/local;
- assenza futura di managed settings su un account o host differente;
- inventario completo e innocuità di tutte le variabili d'ambiente ereditate;
- equivalenza della configurazione su versioni Claude CLI diverse dalla
  `2.1.312`.

Questi limiti non richiedono un cambio di architettura in questa iterazione, ma
impediscono di descrivere la CLI come priva di ogni componente built-in. La
conclusione verificata è più stretta: la superficie invocabile del modello è
limitata ai due tool MCP, i subagenti sono rimossi e gli hook non managed sono
disabilitati nella combinazione provata.
